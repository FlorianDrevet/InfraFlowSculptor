## Correctif du timeout SQL et verrou de reprise — 2026-10-24

### Cause et correction livrée dans la référence IFS

Le rapport PRD a été généré à 09:04:37.0127438Z et indique Connection Timeout Expired pendant le post-login, avec complete=14027 ; le journal a marqué data-access Started à 09:03:03Z. L’Activity Log Azure consigne le début de la reprise serverless à 09:04:41.918923Z, puis sa réussite à 09:05:41.935622Z. Les événements sont dans la même minute, mais ces horodatages ne prouvent pas l’ordre exact du déclenchement de la reprise : son événement est enregistré 4,9 secondes après la génération du rapport. Le timeout SQL transitoire est établi ; le démarrage à froid est une cause probable, pas certaine. L’ancienne fonction ne retentait que les erreurs de propagation des permissions.

Le commit local 5db5a76 fixe IfsRelease.psm1 : délai de connexion SQL explicite de 120 secondes et nouvelles tentatives bornées à dix minutes pour les timeouts de connexion et erreurs SQL transitoires. Un test Pester reproduisait le timeout post-login avant le correctif. Après correction, 54 tests du module puis 123 tests de la suite release-module passent ; les validations Bicep, déterminisme, YAML et manifeste passent aussi. PSScriptAnalyzer ne relève aucune erreur et conserve un avertissement antérieur sans rapport avec ce changement. Le correctif n’est pas encore dans l’artefact shop42 N #759.

Dans cette session, la lecture du journal avec l’identité Azure CLI personnelle a été refusée : l’identité ne possède pas Storage Blob Data Reader sur le stockage PRD.
